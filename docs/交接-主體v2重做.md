## 2. 下一個 session 的工作流程（每個主體都照這個做）

### 步驟 A：開場先問使用者（只問一次，不要拖）

1. 「哪幾個主體最醜、最想先改？」（14 個一起重做很久，先處理最不滿意的）。
2. 「你有沒有自己喜歡的參考圖？」——使用者提供的圖**優先於**我自己找的（他才是審美的標準）。可以請他把圖放進 `docs/參考圖/` 或直接貼在對話裡。
3. 「這些主體主要會被拿來做什麼？」（簡報、社群、片頭…）——影響構圖取捨。

### 步驟 B：找參考圖（**這是整個任務最重要、上次沒做的一步**）

- 每個主體找 **1–3 張**美觀的設計作品（插畫、UI 截圖、海報、3D 渲染…），依下面第 4 節「各主體的搜尋方向」。
- **一定要真的看到圖**。只能看文字的 `WebSearch`／`WebFetch` 不夠。可行的做法：
  1. 用 `WebSearch` 找候選頁面（優先：Dribbble、Behance、ArtStation、Awwwards、Pinterest、Freepik、Unsplash、Wikimedia Commons、各設計獎）。
  2. 取得**圖片的直接網址**（`.png`／`.jpg`／`.webp`）：用 `WebFetch` 問「這個頁面的主圖網址」，或用內建瀏覽器 `navigate` 到頁面，再用 `find`／`read_page`／`javascript_tool`（`document.querySelector('meta[property="og:image"]').content`）取得。
  3. 用 `curl -L -o <scratchpad>/ref/<主體>.jpg "<圖片網址>"`（必要時加 `-H "Referer: <頁面網址>"` 與 `-A "Mozilla/5.0"`）下載到**暫存資料夾**。
  4. 用 **`Read` 工具讀那個圖檔——Read 能直接顯示圖片**。這就是「看到」參考圖的方法。
  5. 如果網站擋 `curl`：用內建瀏覽器 `navigate` 到圖片網址再 `computer screenshot`（常逾時，可重試），或請使用者提供圖。
- 找不到好圖就多搜幾次、換關鍵字；不要因為麻煩就退回「憑想像畫」。

### 步驟 C：分析參考圖（寫成文字，存檔）

為每個主體建立 `docs/主體v2參考/<主體id>.md`，內容：

- 來源網址、作者（若有）、授權狀況（**僅供學習參考，不得把圖或素材放進專案**；專案裡只放自己用程式畫的圖形）。
- 這張圖**為什麼好看**：構圖（視覺重心、留白、比例、網格）、色彩（主色／輔色／點綴的比例，明暗關係）、形狀語彙（圓／方／尖、圓角半徑、線條粗細）、細節（高光、陰影、紋理、小道具）、氛圍。
- **對應到我們的設計語彙**：每個顏色對應哪個色板角色（p、s、a、q、r、ink、light、card、bg、bg2）、哪些細節在 `S.look.detail` 低時要省略。

### 步驟 D：仿照設計

- 以參考圖為目標，重寫該主體的 v2。**要「像」那張圖的比例、層次與細節密度**，而不是只套同樣的原則。
- 用接觸表檢查（見第 5 節），把**參考圖和我們的畫面放在一起 Read 比較**，逐項對照：構圖、比例、配色分配、細節。不像就繼續改，直到使用者看了會說「這個好看」的程度。
- 至少用 3 種風格檢查：`flat`（平面）、一個重質感的（`popart` 或 `watercolor`）、一個像素類（`pixel8`）；3D 主體用 `cel3d`、`matte3d`、`clay3d`。

### 步驟 E：紀錄與驗證

- 更新 `docs/主體v2參考/<主體id>.md`（最後做成什麼樣、和參考圖還差什麼）。
- 跑冒煙測試（`?all=1`）、`npm run typecheck`、`npm run test:audio`、`npm run build`。
- 改完**請使用者逐個主體看**（用 v1／v2 開關比較），不要一口氣全改完才給他看；每做完 2–3 個就請他確認方向。

## 3. 不可違反的技術約定（改設計時要守）

1. **不改 v1**（`src/engine/subjects/*.ts` 與 `src/engine/three/scenes/*.ts` 的行為與外觀）。v1 的 `ball.ts` 多了幾個 `export`（軌跡函式與常數），是為了讓 v2 重用，不要拿掉。
2. **時間結構沿用 v1**：`loop`、`key`、`hero`、`events`、`cues`、`track` 要和 v1 一致（動效風格、音樂對齊、音效提示點、導出都靠它們）。3D 的跳躍姿態用 `mascotPose`。
3. **顏色只能用色板角色**（`'p' 's' 'a' 'q' 'r' 'ink' 'light' 'card' 'bg' 'bg2'`），或用 `darken(S.pal.x, n)`、`mix(...)` 由角色算出。不能寫死色碼，否則 136 種圖像風格就換不了色。
4. **所有東西透過 Brush（`S`）畫**，圖像風格才會套上去：`S.circle／ellipse／rect／poly／blob／line／curve／arc／text`，選項 `{ alpha, stroke, lw, outline, flat, shadow, hl, mode, drawOn, w, cap, outlined }`；`S.push／pop／translate／rotate／scale／stretch／jitter`；`S.col(role)`、`S.pal`、`S.look.detail`（0–1，低於約 0.45 要省略細節）、`S.measure(str, size, font)`。
5. **動畫是時間的純函數**：只用 `M`（MotionCtx）的 `u`、`tw(a,b,'o'|'i'|'io')`、`seg`、`io/out/in`、`stag(i)`、`fl(id, amp)`、`snap`、`jit`、`pulse`、`beat`、`M.mv`（動效風格參數：`squash`、`antic`、`over`、`follow`、`exag`、`noodle`、`rigid`、`wind`、`float`、`typeWriter`、`typeScramble`、`typeWave`、`parallax`、`beat`…）。**不要累積狀態**。要讓動效風格有感，就要讀 `M.mv`。
6. 畫面座標：設計單位，**短邊固定 400**（Hu=400，Wu=400×長寬比；16:9 時約 ±355 × ±200），中心是 (0,0)，y 向下。寬度可能是直式（`env.Wu < 520`），要能收合。
7. 3D 場景：在 `three/scenes/v2/` 寫 `build…2(ctx): SceneInst`，用 `kit.mesh(geo, color, {outline,shadow})`、`geoFactory(kit.coarse)`、`kit.material`、`kit.shadowCatcher`、`motion3d`、`appear`；場景編號（`Scene3DId`）已有 `island2／shapes2／text2／character2／terrain2`。**三角面要少**（低多邊形與線框模式用 `kit.coarse`）。
8. 效能：640×360 每幀不超過約 6 ms（`?bench=1`）。文字逐字繪製（旋轉徽章）最貴。
9. 低細節風格（像素、1-bit）要自動變簡單：用 `S.look.detail` 判斷。

## 5. 工具：接觸表（上個 session 做的，已放在 `scripts/design-sheet/`）

目的：把主體在多個時間點畫成一張圖，**存成 PNG 再用 `Read` 看**（內建瀏覽器的截圖常常逾時，這個方法穩定）。

```bash
# 1) 開發伺服器（用 preview_start 啟動 .claude/launch.json 的 style-fusion，埠 5199）
# 2) 在暫存資料夾啟動 PNG 接收器（背景執行）
node scripts/design-sheet/recv.mjs "<scratchpad>/sheets"
# 3) 內建瀏覽器開（會自動畫完並把 PNG 傳給接收器）：
#    http://localhost:5199/scripts/design-sheet/sheet.html?s=mascot&v=2&style=flat&n=6&cols=3&w=480&t0=0.04&t1=0.96&name=mascot_v2_flat
# 4) 用 Read 讀 "<scratchpad>/sheets/mascot_v2_flat.png"
```

網址參數：`s` 主體 id、`v` 1 或 2、`style` 圖像風格 id（`flat`、`popart`、`pixel8`、`watercolor`、`cel3d`、`matte3d`、`clay3d`、`stickynote`…）、`m` 動效風格 id（可選）、`n` 格數（≤12）、`cols`、`w` 每格寬、`t0／t1` 時間範圍（0–1）、`name`。`?all=1`＝冒煙測試（結果在 `window.__errs`，用 `javascript_tool` 讀；`__n` 是渲染次數）；`?bench=1`＝每幀耗時（`window.__bench`）。

用完請關接收器（埠 5555）。這個資料夾**不在 `tsconfig` 的 include 裡**，不影響 `npm run typecheck`，也不會被打包。

### 用 Read 比較「參考圖 vs 我們的畫面」

把參考圖下載到 `<scratchpad>/ref/xxx.jpg`，接觸表存到 `<scratchpad>/sheets/xxx.png`，**連續 Read 兩個檔案**對照（構圖、比例、配色、細節）。必要時用 `n=1&w=960` 把單一畫面放大看細節。

## 6. 已知的環境陷阱（延續 `HANDOVER.md` §11）

- bash 工具處理含引號／中文的長 heredoc 會壞：長檔案用 **Write 工具**寫，再用短的 python 腳本拼接。`python` 可用，`python3` 不行。
- 內建瀏覽器常常是「隱藏」的：`requestAnimationFrame` 不會跑、截圖逾時；接觸表只靠 `Renderer.render`，不受影響。實際播放要測就用 `setTimeout` 版的 rAF 臨時頁面。
- 開發模式 `window.__sf = { audio, clock, store, themes, templates }`。
- 測試完要刪掉暫存頁面與 PNG 接收器；不要在專案裡留下 `design-sheet.html` 之類放在根目錄的檔案。
- `projects/` 與 `docs/*.json`（鴨子等）是**使用者自己的作品**，不要動。
