第二版依你的回饋改了四件事：

1. **要有亮眼的功能** → 第 2 節列出五個亮點，前兩個是 Agent。
2. **版面要清爽，複雜功能放進階** → 預設是「簡潔模式」，畫面上只有舞台、一條播放列、場景帶、Agent；其餘收在「進階」。

## 1. 方向

**一句話**：把 Style Fusion 從「挑風格、抄數字」變成「跟 Agent 說一句話就有一段自己的動畫，指著時間點說哪裡要改，再套上 136 種風格，排成一支片子交付」。

工作單位從「一組混合」換成「一個專案」：專案裡有場景，場景裡放的是**生成的內容**（Agent 做的、可以對話修改）或**內建模板**（現有 21 個主體，只能換字、換風格）。

現有的東西不丟：只有一個場景、放內建模板的專案，行為就是今天的混合器。

## 3. Agent：直接生成與對話修改

### 3.1 怎麼不走 API 就呼叫 Claude

**先講限制**：純網頁本身沒辦法直接呼叫 Claude——瀏覽器裡的網頁要嘛帶 API 金鑰，要嘛得有一個「已經登入 Claude 的東西」幫它轉手。你記得的能力，我理解是下面的 A 或 B：

| 方案 | 做法 | 不用 API 金鑰？ | 哪種開法能用 | 我的判斷 |
| --- | --- | --- | --- | --- |
| **A　本機橋接（建議）** | 你平常用 `start.bat` 開 App，它本來就會在你電腦上跑一個小伺服器。2.0 讓這個伺服器多做一件事：把 App 的請求交給你電腦上**已經登入的 Claude Code**（命令列的無畫面模式），再把結果傳回 App | 是，用的是你 Claude Code 的登入 | 只有 `start.bat`／`start-dev.bat` | 最符合你要的；不是 exe，還是網頁加上你本來就在用的啟動器 |
| B　放進 Claude 的 Artifact | 把 App 發佈成 claude.ai 上的 Artifact，用 Artifact 內建的「問 Claude」能力 | 是，用的是觀看者的 Claude 帳號 | 只有在 claude.ai 裡開 | 可行性要另外評估（檔案大小、外部字體、能力的輸入長度上限）；App 會被綁在 claude.ai 裡 |
| C　手動轉貼（保底） | 現在的做法：複製提示詞 → 貼到任何 LLM → 把結果貼回來 | 是 | 全部（含雙擊單檔、線上版） | 保留當退路 |
| D　API 金鑰 | 使用者自己填金鑰，網頁直接呼叫 | 否 | 全部 | 你說不要，不做 |

**建議：A 為主、C 保底。** 同一個 Agent 面板，偵測到本機橋接就直接生成；偵測不到（雙擊單檔、線上版）就變成「複製提示詞／貼回結果」兩顆按鈕，流程與驗證完全相同。

**方案 A 已經用實驗確認可行**（2026-11-11，結果見 3.6 節）。

**還沒驗證、要注意的**：
- 實驗是從我這邊的指令列啟動橋接，不是從 `start.bat`；正式接進 `start.bat` 的伺服器時要再測一次。
- 用訂閱登入的 Claude Code 給你自己的本機工具呼叫，屬於個人使用；如果之後要把這個 App 給別人用（別人的電腦上也要裝 Claude Code 並登入），條款上是否允許我不確定，要另外查。
- 會佔用你 Claude 訂閱的用量額度（一次生成約 8 千～1.2 萬個輸出 token，大部分是思考）。

### 3.2 Agent 能做什麼、不能做什麼

| | 生成的內容 | 內建模板（21 個主體） |
| --- | --- | --- |
| 是什麼 | Agent 產生的動畫：圖層＋關鍵影格＋事件＋音效點，就是現有的「自訂動畫主題」格式（`themes.ts`） | 程式畫的主體（狐貓、光圈標誌、3D 產品…） |
| Agent 能不能改 | **能**：對話修改形狀、時間、動作、文字 | **不能**（你指定的）。只能換字、換風格、換動效、調微調 |
| 套風格、動效、後期 | 能（和模板一樣） | 能 |
| 介面上怎麼分 | 場景縮圖右上角有一個小標「生成」 | 沒有小標 |

選到內建模板的場景時，Agent 輸入框變成停用，顯示一行說明：「這是內建模板，不能用對話修改。要可以改的版本，請讓我生成一個新的。」

Agent **不會**做的事：不碰專案程式、不讀你電腦上的檔案、不上網。它只收「現在的動畫內容＋你的話＋時間點」，只回「改過的動畫內容」。

### 3.2.1 生成的流程：先選風格模板，再用初始提示詞

Agent 模式的第一步不是「直接說要一個什麼」，而是**先選風格模板**（現有的 12 個起點與 56 個案例配方，之後也可以是你自己的收藏）。流程：

```
① 選風格模板 ──▶ ② 輸入框自動帶好「初始提示詞」 ──▶ ③ 需要才改 ──▶ ④ 送出生成
```

- **初始提示詞的內容**（由 App 依模板產生，沿用現有「給 Claude 的提示詞」的整理方式）：
  - **主題**一行：預設是這個模板的示範主題（例如「咖啡杯冒煙，店名從杯口升起」），反白顯示，是最常需要改的地方。
  - **長度**：預設 8 秒。
  - **風格規格**：色板、線條、質感、動效與緩動、幀率。預設收合成一行「風格規格（自動附上，可展開修改）」。
- **不改也能送**：直接按「生成」就得到這個模板的示範內容；要自己的內容，改主題那一行即可；要更細的控制，展開風格規格再改。
- **換模板**：輸入框上方顯示目前的模板（縮圖＋名稱＋「換一個」）。換模板時，如果你改過主題，主題那一行會保留，只換風格規格。
- **生成之後**：這個場景就綁定這個風格模板；之後仍然可以在風格牆換風格，或用對話繼續修改內容。
- **手動模式**（沒有連上 Claude）也是同一個初始提示詞，只是「生成」變成「複製提示詞」。

### 3.3 對話修改的流程

```
你：  [@03.2s 煙升起]  這裡煙太快，慢一半；杯子再大一點
        │
App： 組成請求 ＝ 格式說明 ＋ 現在的內容 ＋ 你的話 ＋ 時間點附帶的資料
        │
Claude：回傳「修改清單」（改哪個圖層、哪個關鍵影格、改成什麼）
        │
App： ① 驗證（沿用 parseTheme；不合格就自動帶著錯誤訊息重問一次）
      ② 套到一份副本上，舞台立刻預覽
      ③ 在對話裡顯示一張「修改卡」
        │
你：  按「套用」（變成一步可以復原的動作）／「比較」（按住看原本的）／「放棄」
```

修改卡的內容：一句摘要（「煙的上升從 0.8 秒改成 1.6 秒；杯子放大 20%」）、動到的時間範圍（時間軸上以強調色標出）、三顆按鈕。**沒有按「套用」之前，專案不會被改。**

### 3.4 時間點（時間戳）

- **加入方式**：播放列與 Agent 輸入框旁都有「附上時間點」。按下去，目前播放頭的時間變成輸入框裡的一個標籤，例如 `@03.2s 煙升起`（後面的名字是那個時間點最近的事件）。在時間軸上拖一段範圍則變成 `@03.2–04.0s`。一則訊息可以附多個。
- **Agent 拿到什麼**：每個時間點附帶 ① 時間（秒與佔循環的比例）② 前後 0.3 秒內的事件與關鍵影格 ③ 那一刻各圖層的位置、縮放、透明度 ④ 那一格的縮圖。所以「這裡」是有具體所指的。
- **回覆裡的時間點可以點**：Agent 回「我把 03.2 秒的煙改慢了」，其中的時間是連結，點了播放頭就跳過去。
- **對內建模板**：時間點一樣可以加，但只用在配樂（重拍、口播起訖）與場景標記，不會送去改模板。

### 3.5 技術做法、風險、工作量

- **橋接**：`start.bat` 啟動的本機伺服器加一個只聽 `127.0.0.1` 的端點，帶一次性的通行碼（防止其他網頁偷用）；收到請求就以無畫面模式啟動 Claude Code，不給任何工具權限，把輸出串流回網頁。
- **格式**：提示詞沿用並整理現有的 `themeAiPrompt()`；回傳用「修改清單」而不是整份重寫（小修改比較快、也比較不會把沒提到的地方改壞），第一次生成才回整份。
- **驗證**：`parseTheme` 已經有（大小、圖層數、數值範圍）；再加每幀耗時檢查，超過 6 ms 就請 Agent 簡化。
- **復原**：每次「套用」是復原歷史的一步；對話紀錄跟著專案存。
- **風險**：① 一次要等十幾秒到一分鐘，要有進度與取消；② 生成的內容可能不好看——所以「比較／放棄」必須順手，並且可以說「再試一次」；③ Claude Code 沒裝、沒登入、版本太舊時，要給清楚的說明並退回方案 C；④ 內容會送到 Claude（你自己的帳號），面板第一次開啟要講明白。
- **工作量**：橋接與生成　中；對話修改＋修改卡　中；時間點　小～中。先做半天的小實驗確認方案 A 可行。

### 3.6 實驗結果（2026-11-11）

做法：一個只聽 `127.0.0.1` 的小伺服器（帶通行碼、檢查來源），收到請求就以無畫面模式啟動這台電腦上的 Claude Code 2.1.311，不給任何工具、在空的暫存資料夾裡執行，把輸出串流回來。提示詞用現有的 `themeAiPrompt()` 加上「初始提示詞」（主題、長度、風格規格）。實驗程式放在 git 忽略的 `out/`，做完已刪除；正式程式沒有動。

| 測試 | 結果（實測） |
| --- | --- |
| 沒帶通行碼／來自外部網站的請求 | 都回 403 |
| 偵測登入狀態 | 未登入時回報「已安裝、未登入」；登入後回報已登入 |
| 短請求 | 約 4 秒，逐字串流 |
| **生成**（主題：咖啡杯冒煙，店名從杯口升起，8 秒） | 第一次就通過 `parseTheme` 驗證；**55.9 秒**（前 47.9 秒在思考，沒有文字輸出）；3 個頂層圖層、1 個事件 |
| 生成，思考深度調低 | 也是第一次就通過驗證；**37.6 秒**（前 31.6 秒沒有輸出） |
| **修改**（附時間點 3.2 秒：煙慢一半、杯子大 20%、其他不動） | 第一次就通過驗證；**23.8 秒**；只動了 20 個數值——杯子的縮放全部 ×1.2 並調整位置讓它仍坐在碟子上、三道煙的關鍵影格時間延後、煙的起點配合杯子上移。其他圖層完全沒變 |
| 每幀耗時（640×360，30 格平均） | 扁平 0.54 ms、普普 5.26 ms、水彩 3.92 ms，都在 6 ms 內 |
| 套風格 | 生成的內容套扁平與普普風格都正常畫出 |

**看過畫面之後的評語（接觸表，6 個時間點）**：
- 內容對：有杯子、碟子、三道煙、店名；修改後杯子確實變大。
- **不夠好看**：店名很小、構圖偏空、杯子是從上方落下而不是設計感的進場。這是「一次生成」的水準，離你對主體 v2 的要求有距離。所以「比較／放棄／再試一次」與對話修改必須順手，初始提示詞也要把構圖與字級的要求寫進風格規格。
- 我只看了靜態的接觸表，沒有看實際播放。

**結論與對設計的影響**：
1. 方案 A 可行，定為主要做法。
2. **等待時間是主要問題**：生成 40～60 秒、修改約 25 秒，而且大半時間沒有任何輸出。介面要顯示已等待的秒數與「通常需要 40～60 秒」，並可取消；生成期間舞台與其他操作不能被鎖住。
3. 思考深度做成設定：預設「快」（約 40 秒），「仔細」約 60 秒。
4. 修改用「回傳整份」就夠準確（這次只動了該動的 20 個值）；「只回修改清單」可以更快，列為之後的優化，不是必要條件。
5. 還沒測：連續多輪修改會不會越改越偏、較複雜的內容（十幾個圖層）、格式不合格時的自動重問、從 `start.bat` 啟動。

## 4. 版式設計

設計圖在畫布上（連結見最上面），共六張：簡潔模式（含 Agent 對話、時間點、修改卡）、風格牆、進階模式、Agent 面板的其他狀態（第一次打開／選到模板／手動模式）、手機、全螢幕展示。設計圖只畫了深色主題；舞台裡的畫面是用簡單形狀示意，不是實際渲染。

### 4.1 原則：預設清爽，進階才展開

上一版一打開就有素材庫、時間軸三列、檢查器五個區塊。這一版分兩層：

| | 簡潔模式（預設） | 進階模式（頂列一顆開關） |
| --- | --- | --- |
| 畫面上有什麼 | 舞台、一條播放列、一條場景帶、Agent 面板 | 再加上：素材庫（左）、完整時間軸（標記／場景／配樂）、右側多三個頁籤（調整／聲音／規格） |
| 換風格 | 播放列的「風格」鈕 → 風格牆；或「重抽」；或直接跟 Agent 說 | 素材庫逐一挑、調比重 |
| 改內容 | 跟 Agent 對話；模板在場景帶點一下就能改字 | 微調滑桿、自訂色板 |
| 排片子 | 場景帶：加場景、拖長度 | 標記、轉場、配樂段落、聲部混音 |
| 給誰 | 找靈感、快速出一段、給客戶看 | 要細調與交付規格的人 |

開關的狀態會記住。進階功能第一次被需要時（例如點了場景帶上的配樂細線），會提示「這在進階模式裡」並可一鍵切過去。

### 4.3 進階模式

簡潔模式的四塊位置不變，再多出：左側素材庫（296）、場景帶展開成完整時間軸（標記／場景／配樂三列）、右側面板多三個頁籤（Agent｜調整｜聲音｜規格）。也就是上一版的三欄版面，Agent 成為右側的第一個頁籤。

### 4.4 風格牆

按播放列的「風格」：舞台換成 3×3 的格子，每一格是**同一段內容**套不同風格，全部同時在動。上方一列可以選「全部／相近的／對比強的／3D」，右上「換一批」。點一格 → 套用並回到舞台；滑過一格顯示風格名稱與「加進混合」。

效能：九格共用現有的縮圖排程器（有時間預算），每格 1/3 解析度；3D 風格一次最多三格。

### 4.5 手機


### 4.7 視覺規則（沿用上一版，摘要）

- **顏色**：中性色九階（沿用現有深色／淺色主題）＋琥珀一個色相。一個畫面只有一顆實心強調色按鈕（導出；Agent 面板裡是「套用」，兩者不會同時是主要動作的焦點——修改卡出現時「套用」是實心，「導出」維持實心但在頂列）。選取＝強調色外框＋淡底。舞台裡的顏色是作品，不受限。
- **字級**：專案名稱 16、區塊標題 13 粗、內文 13（手機 14）、說明 12、時間碼等寬 13。中文最小 12。數字一律等寬。
- **間距**：4 的倍數（4／8／12／16／24）。頂列 48、播放列 48、場景帶 64、可點的東西桌面 ≥ 32、手機 ≥ 44。
- **層級**：舞台（最暗、無邊框）→ 面板 → 面板內的卡片 → 浮層 → 對話框 → 提示訊息。
- **位置固定**：每顆按鈕有固定的格子；會變的字用等寬數字加最小寬度；開關只換圖示不換寬；進度顯示在原來那顆按鈕裡；浮層蓋在上面不推擠；Agent 面板收合時舞台變寬，但播放列的按鈕順序與相對位置不變。

## 6. 必須守的限制，逐條對照
