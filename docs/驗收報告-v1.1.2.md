# Style Fusion v1.1.2 驗收報告

> 版本：1.1.2（2026-10-02）　性質：修訂版（只修試聽與音樂渲染的行為，沒有新功能）
> 前一版：`驗收報告-v1.1.1.md`。完整更新內容見 `CHANGELOG.md`。

---

## 1. 這一版要解決的問題

**使用者回報**：在「聲音方案」按某個方案的 ▶ 試聽（例如 8-bit）之後，**播放中**再去換「曲風」，聲音還是原本那個曲風；必須先停止、再按一次開始，才會用新的曲風。這不符合一般的操作邏輯。

**原因**：試聽是把「按下那一刻」的歌渲染成一段音訊播一遍就結束，之後換曲風、調性、速度、種子，引擎不會再去動它。而且試聽只播一遍，播完之後換曲風也不會再響。

## 2. 現在的行為

| 操作 | 結果 |
| --- | --- |
| 按方案的 ▶ | 循環播放；圖示變成暫停；聲音方案標題旁顯示「試聽中 · 換曲風、調性或速度會自動跟著換」 |
| **試聽中換曲風／調性／速度／重新作曲／對齊動畫開關／換圖像風格或動效風格** | **自動換成新的那首歌**（同一個聲音方案）。舊聲音繼續播到新的渲染好（約 0.2–0.5 秒，按鈕轉圈），再淡出舊的、淡入新的 |
| 連續快速點好幾個曲風 | 只算最後一個，不會每點一下就重算，也不會疊在一起 |
| 試聽中選另一個聲音方案卡（不是 ▶） | 試聽不被打斷（它只改變「正式使用」的方案） |
| 試聽中按另一個方案的 ▶ | 換過去（淡出淡入，不會兩份疊在一起） |
| 再按同一個 ▶ | 暫停 |
| 暫停後再換曲風 | 不會自己開始響 |
| 主開關關閉、離開「聲音」分頁、瀏覽器分頁被隱藏 | 試聽自動停止 |
| 拖曳「音樂音量」 | 試聽音量即時跟著變 |
| 背景音樂（喇叭開啟）時換曲風 | 本來就會跟著換，這次一併確認；只換音效包不會重新渲染音樂 |

## 3. 做了什麼改動

- 計畫識別碼拆成三層：`songKey`（同一首歌）、`musicKey`（歌 + 聲音方案）、`key`（再加音效包）。引擎用 `songKey` 判斷「試聽要不要換歌」，用 `musicKey` 判斷「背景音樂要不要重新渲染」。
- 引擎新增渲染快取（最近 4 筆）：試聽與背景音樂共用，同一首歌只算一次；來回切換曲風時命中快取，幾乎立刻切換。
- 試聽改成可取消、可跟隨的流程（`runAudition` / `followAudition`），換歌時以淡出淡入交接。

## 4. 驗證

| 項目 | 方法 | 結果 |
| --- | --- | --- |
| 你描述的操作 | 瀏覽器實測：主畫面暫停，試聽 8-bit NES（電影管弦，11.2 秒），真實點擊 K-Pop 曲風 | 約 0.3 秒內換成 K-Pop（8.4 秒），仍是 8-bit NES，仍在循環 |
| 連續換曲風 | 60 毫秒內連換 5 個曲風 | 只有 1 個播放中的聲音，且是最後一個（流行） |
| 調性、種子、速度、對齊動畫 | 逐項改 | 每項都換成新的歌，同時只有 1 個播放中的聲音 |
| 選另一個方案卡 | 試聽 8-bit 時選 Game Boy 卡 | 試聽不受影響 |
| 切換方案的 ▶、暫停 | 按 MIDI 的 ▶ 再按一次 | 切過去時只有 1 個聲音；再按一次全部停止 |
| 暫停後換曲風 | 停止後換 R&B | 不會自己開始響 |
| 離開分頁 | 試聽中切到「處方」 | 立即停止 |
| 背景音樂 | 開聲音，換搖滾、只換音效包、換回自動 | 搖滾時換歌；只換音效包時音源與渲染都沒動；換回自動時換回原曲 |
| 自動檢查 | `npm run test:audio`、`tsc` | 全過（新增識別碼測試：換方案＝同一首歌、換音效包不重新渲染、換曲風／種子／速度／調性／對齊動畫＝另一首歌） |
| 主控台 | 讀取錯誤訊息 | 無 |
