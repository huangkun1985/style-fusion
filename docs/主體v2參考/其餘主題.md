## 共用程式的改動（影響範圍很小，v1 不受影響）

- `brush.ts`：`Brush.skew(kx)`（斜切）、`Brush.text` 的 `glow: false` 可覆寫風格的發光。
- `postfx/PostFX.ts` 與 `renderer.ts`：WebGL 被瀏覽器收回時自動重建（使用者回報 8-bit 風格看起來不像像素的疑似原因）。
- `scripts/design-sheet/sheet.ts`：接觸表加 `ar`（長寬比）參數與 `__r`、`__probe` 測試掛鉤。

## 驗證（2026-10-07）

- 每個主體都看過接觸表（至少 `flat`；多數另看 `popart`、`cyberpunk`、`pixel8` 之一）。**3D 主體主要用 `cel3d` 看過**；另外看了 3D 角色的 `clay3d`（發現跳起來時頭被切掉，鏡頭往後拉：`dist` 13.4、目標高 2.0）與 3D 文字的 `matte3d`（字母和擠出層都變成近白色，疊層的色彩差異消失，只剩明暗，仍可讀）。其餘 3D 主體×材質的組合沒有檢查。
- 冒煙測試 `?all=1`：1260 次渲染零例外。`?bench=1`：2D v2 每幀 0.1–2.3 ms。`npm run typecheck`、`npm run test:audio`、`npm run build` 通過。

# 第二輪修改（使用者看過後的回饋，2026-10-07）

回饋原文：風景視差太單調、層次弱；抽象流動不夠絲滑、運動死板；3D 主題很多會閃爍（主要是陰影）；3D 文字很寡淡；3D 地形像半成品；3D 體素太簡單。

## 3D 閃爍：查到的原因與修法

我先用「連續畫極小時間間隔的幀、數相鄰兩幀差很多的像素比例」的探針（`scripts/design-sheet/sheet.ts` 的 `__flick`、`__flickScan`）找閃爍，再逐個原因驗證：

1. **接觸陰影平面與展示台頂面共面（z-fighting）**——**有量測證據**。`shadowCatcher` 平面在 y=0，所有展示台頂面也在 y=0，深度緩衝無法決定誰在前，相機一動，陰影就一塊一塊忽有忽無。用相機環繞的動效、同一個場景、把平面還原成 y=0 且不做 polygonOffset：相鄰幀差異像素 2.31%；修正後 1.58%（多出的 0.7 個百分點就是深度打架）。修法：抬高 0.012 並加 `polygonOffset`（`materials.ts`）。
2. **側面的陰影痘（shadow acne）**——**看得到**（3D 文字字母側面有鋸齒條紋，每幀變）。光線貼近側面方向時，`normalBias 0.03` 太小；改成 0.09、`bias −0.0015`，陰影貼圖 1024→2048（縮圖 512→1024），過濾改成 `PCFSoftShadowMap`（`common.ts`、`stage.ts`）。
3. **我自己做的 3D 文字：擠出層和正面互相穿插**——相交的曲面在相機移動時鋸齒位置每幀跳動。改成「前後相接、不重疊」的薄片（每層 `receive: false`，`kit.mesh` 新增 `receive` 選項）。

**沒確定的**：以上是我在自己的接觸表工具裡能重現、量到的。使用者的實機（真的 GPU、真的播放）有沒有別的閃爍來源（例如多個 WebGL 內容同時存在被收回，見 CHANGELOG），我沒辦法確認；請你看一次實際播放。`PCFSoftShadowMap` 與 2048 貼圖會讓陰影更穩但稍貴（本機量到每幀 CPU 提交 0.8–2.0 ms，GPU 實際耗時沒量到）。v1 的 3D 場景共用同一套燈光與陰影設定，所以也一起受益。

## 這輪的限制

- 3D 主體仍只主要用 `cel3d` 看，另外看了體素在 `clay3d`、地形在 `wire3d`，其餘材質沒有逐一檢查。
- 體素的場景很擠，部分角度會被樹遮到風車；沒有針對所有 3D 運鏡（環繞、俯衝）逐一檢查。
- 3D 文字的環在鏡頭拉近時頂端會被切到。
- 抽象流動「絲滑」是用曲線與時間函數改善，沒有真的播放確認手感。
