# UI 介面（ui）v2 第三版：參考圖分析與仿照紀錄

> 第二版使用者評「還不夠精緻」，並要求「找個案例來參考」。第二版只是「參考了結構」（大數字、強調一根長條、清單有圖示底），沒有逐項對照。第三版改成**選定一張參考圖（Statistics／Class Detail，同一位設計師的一組）**，量它的座標與字級，用同樣的座標重畫。下面「第三版實作」是最新的；其後的內容是第二版的分析，仍然有效。

## 第三版：逐項對照 Statistics（參考圖 800 px 寬，手機螢幕 330 px ≈ 390 pt，換算 0.846 px/pt）

整個螢幕直接用參考圖量到的 pt 座標畫（390×844），再縮放 0.44 放進手機：

| 項目 | 參考圖量到的 | 實作 |

| 主視覺卡 | 高約 320；頂部標題條（圓餅圖示＋藍色「Overall Presence」11.5）＋分隔線；85% 約 30 pt；綠色變化量膠囊；「STUDENT PRESENCE」9.5 pt 大寫灰；右側**描邊按鈕**「View All ↗」；再一條分隔線 | 同 |

**第二版的錯誤在哪裡**：卡片用陰影與大圓角（18–22）、字級偏大且不統一、沒有邊框、導覽是色塊膠囊、沒有檔案圖示與頭像、沒有描邊按鈕與分隔線。參考圖的精緻感幾乎全來自這些「小」東西。

## 第三版踩到的坑

- **髮絲邊框的線寬**：強制描邊的線寬是 `2.2 × lw`（在目前座標系的單位）。我先乘了兩次倍率，邊框變成一條粗灰線；改成 `lw: 0.42`，在 pt 座標下約 1 pt（0.44 設計單位）。
- **導覽底板要有圓角**：方形底板會凸出手機螢幕的圓角；用多邊形畫出底部兩角圓弧（半徑 56 pt）。
- **旋鈕、愛心的長陰影**：風格的陰影套到小圓上很髒，`shadow: false`。
- 文字在 pt 座標下大小要乘 0.44 才是設計單位：小於 13 單位的字不描邊、像素風格下小於 3.6 格高的字改畫成色條，判斷都用「乘過 0.44 後的單位」。

## 第四版：使用者說「還是太醜、不像頂級 UI 設計師、連愛心形狀都很奇怪」（2026-10-06）

自己用設計師的眼光挑出的問題，和修法：

| 問題 | 修法 |
| --- | --- |
| **顏色太多**：紅、藍、綠、黃四種原色亂用（環形圖三色、頭像黃藍、清單圓點、檔案圖示各一色），像玩具 | **只有一個強調色 `p`＋ink 的不同濃度＋語意綠 `q`**；環形圖用 p／深石板／淺石板（`mix(ink, card, .14/.72)`）；圖示底用 `mix(p, card, .87)` 或淡灰；提醒色用 `mix(a, ink, .38)` 才和白底有對比 |
| **愛心是 6 個點湊的團塊** | 真正的心形參數曲線（`16sin³t`、`13cos t − 5cos2t − 2cos3t − cos4t`），30 點平滑；收藏鈕是圓形淡灰底，平時是描邊心、點到時填 `p` 並彈起 |
| **兩側卡片和手機是兩種設計語言**（陰影＋大圓角 vs 髮絲邊框） | 全部同一種卡片：髮絲邊框（`mix(card, ink, .085)`、`lw .32`）＋一道偏移 1.7 的極淡下緣陰影＋同一個圓角 12 |
| **長條是膠囊形** | 參考圖的長條只有頂端圓角、底部是平的：用多邊形畫 |
| **頭像是黃藍剪影、檔案圖示字太小** | 縮寫字母圓形頭像（J／M）；帶摺角的文件圖示（不再放看不清的 PPT／HTML 字） |
| **手機邊框太厚、通知貼著標題** | 邊框縮到約 3.5 單位；通知膠囊高 46、離標題多留空 |
| 環形圖中間的金額太寬 | 環半徑 37、金額字 12.5 |

另外「Flow／TOTAL BALANCE」改成「Spending／TOTAL」，是環形圖的語意更貼近。

## 使用者截圖指出的缺陷（第三版剛做完就被罵，記下來）

使用者貼了舞台截圖：**通知橫幅（深色大膠囊）蓋住了「Statistics」大標題與右上角加號鈕**，只剩一個「S」和半個灰圓露出來，頂部一塊黑；另外手機佔滿舞台全高、沒有留白。這兩點我在接觸表裡其實看到了（通知蓋住標題的那一格），卻當成「動畫中的暫時狀態」放過。教訓：**動畫的每個狀態都要當成成品檢查，不能只看靜態的中間幀；要用舞台實際的長寬比（「填滿」約 1.88:1）看，不只 16:9。**

修法：通知改成 **iOS 即時動態的做法——動態島展開成一條深色膠囊**（寬 112→346、高 32→50、位置 y 30→44，內容在展開過半後淡入；展開時原本的島藏起來，不然會從膠囊上緣凸出一塊），不再蓋住標題。`track()` 的追蹤點改成跟著膠囊。手機縮放 0.44→0.41（高約 360，和 v1 一樣，上下留白）。接觸表工具加了 `ar` 參數（`&ar=1.88`）可指定長寬比。

## 第三版驗證（2026-10-06）

- 接觸表（六格與放大單格）：`flat`、`popart`、`pixel8`、`cyberpunk`、`watercolor` 都看過。`flat` 與 `cyberpunk` 最好；`popart` 的粗黑邊讓小字偏糊但結構清楚；`pixel8` 是乾淨的線框稿；`watercolor` 的手繪暈染會讓 6–9 單位的小字變糊（風格本身的特性）。
- 冒煙測試 `?all=1`：1260 次渲染零例外。`?bench=1`：ui v2 每幀 1.2 ms（v1 0.6 ms）。`npm run typecheck` 通過。

## 與參考圖還差什麼（誠實版）

- 圖示是簡化的幾何線條，不是真正的圖示庫；檔案圖示裡的「PPT」「HTML」字在小尺寸下很擠。
- 頭像是色圓加人形剪影，不是照片。
- 字體用風格的字型，沒有參考圖的 Inter 那種中性無襯線；沒有 semibold 字重可選。
- 只有一支手機一個畫面（參考圖是兩支並排：Statistics 與 Class Detail）；側邊卡片（環形儀表、收藏清單）是我加的，不在參考圖裡。
- 沒有測直式 9:16、其他動效風格、3D 風格。

# 以下是第二版的分析（仍然有效）


日期：2026-10-06　檔案：`src/engine/subjects/v2/ui.ts`（備份 `docs/主體v2重做/2026-10-05/ui.ts`；第一版在 `docs/主體v2初稿/subjects/ui.ts`）

## 參考圖（僅供學習參考，圖檔沒有放進專案）

來源：Dribbble 標籤頁 <https://dribbble.com/tags/mobile-app-dashboard>（作者名未逐一記錄；圖已下載到暫存資料夾用 Read 看過）。先下載 16 張做成接觸表挑選，細看了其中 3 張最適合「要放進各種風格」的淺色 App：

1. **Focus（計時器／任務清單）**：暖橘色單一強調色、白色圓角卡、深色小膠囊按鈕與底部深色導覽、清單每列有圖示底。
2. **Flowlet（錢包）**：環形儀表三色分段加大數字置中、三列消費清單（圖示底＋名稱＋金額＋百分比）、底部深色滑動按鈕。
3. **Statistics（統計）**：大標題、一張主視覺卡（85% 大數字＋綠色變化量膠囊）、**長條圖只強調一根（藍）其餘淺灰、上面一個深色數值氣泡**、清單列有英文縮寫圖示底＋彩色狀態字＋重疊頭像、底部導覽。

## 為什麼好看

- **一個大數字當視覺焦點**（85%、$3,430、13:15），旁邊只有一個小標籤與一個變化量膠囊。
- **三層資訊**：大標題（約 15）／主要內容（8–9）／極小的灰色說明（6），透明度拉開層次。
- **圖表只強調一個資料點**：其餘淺灰、一根用強調色、加深色數值氣泡；有虛線平均線與 W1…W8 軸標。
- **清單列的結構固定**：圖示底（強調色的淡色）＋標題＋副標＋尾端內容（開關、頭像、數值、百分比）。
- **強調色只用一個**，深色（ink）用在小膠囊與通知；卡片白、螢幕底微灰，用間距與圓角（約 18–22）分層，不靠框線。
- **有真實的文字與數字**，不是灰色佔位條——這是第一版最大的缺點。

## 第一版（被評「太醜」）的問題，對照後的診斷

全是灰色佔位條（看起來像空殼）、圖示只是一顆圓、主視覺卡是一大塊紅底加光斑、兩側小卡像貼上去的、沒有資訊層次。

## 對應到我們的設計語彙（顏色一律用色板角色）

| 部位 | 顏色 |
| --- | --- |
| 手機外殼、動態島、通知膠囊、數值氣泡 | `ink` |
| 螢幕底 | `mix(bg, card, .62)` |
| 卡片、清單列、導覽列 | `card` |
| 長條圖（非強調）、進度環底 | `mix(card, ink, .15)` |
| 強調長條、導覽膠囊、大標籤、愛心 | `p` |
| 圖示底 | 強調色混 `card`（`mix(c, card, .82)`），圖示本身是原色 |
| 狀態字／變化量／開關開啟 | `q`（成功）、`a`（提醒） |
| 環形儀表三段、清單點 | `p`、`s`、`q`、`a` |

## 時間結構（與 v1 相同，音效提示點與動效風格照舊）

進場（0–0.16）→ 交錯進場與長條長出（0.06–0.4）→ 開關切換（0.43）→ **點選長條 W7（0.56，漣漪、強調從 W4 跳到 W7、氣泡跳過去、88%）** → 導覽膠囊從首頁滑到統計（0.58–0.7）→ 通知彈出（0.66）再收回（0.86）→ 退場（0.92）。寬畫面左邊多一張環形儀表卡（三段依序畫出、數字跟著長）、右邊一張收藏數＋三列清單卡（愛心彈出在 0.48）。

## 實作重點與踩到的坑

- **小字不描邊**：普普風等粗描邊風格會把 6–9 單位的小字糊成一團黑塊；`size < 13` 的字一律 `stroke: false`，只有大標題保留風格描邊。
- **像素風格讀不出字**：像素化後期把一格像素放大到 `size × 400` 個設計單位（8-bit 約 6 個單位），小於約 3.6 格高的字讀不出來，會變成一團灰。改成「讀不出來的字畫成色條」（用 `S.measure` 量寬度），像素風下變成乾淨的線框稿。這個判斷用 `S.look.post` 裡的 `pixelate` 取像素大小，不是靠 `detail`（只有一個風格設定了 `detail`，其他都是 1，不能靠它）。
- 導覽膠囊要停在圖示正中（圖示間距 40，膠囊從 −60 滑到 +20），第一次寫成 0，停在兩個圖示中間。
- 長條圖的氣泡要避開左邊的小標籤：圖表上緣降低（最高 42）。
- 在 `flat`、`popart`、`pixel8`、`cyberpunk`、`watercolor` 五種風格下都看過。

## 驗證（2026-10-06）

- 接觸表（六格與放大單格）：五種風格都看過；`cyberpunk` 很有 HUD 質感、文字清楚；`watercolor` 是手繪草稿感，淺灰長條對比低所以把灰度調深一點。
- 冒煙測試 `?all=1`：1260 次渲染零例外。`?bench=1`：ui v2 每幀 2.4 ms（v1 1.2 ms，文字多所以較貴），低於 6 ms。`npm run typecheck` 通過。

## 與參考圖還差什麼（誠實版）

- 沒有真實圖示：導覽四個圖示是簡化的幾何形（房子、資料夾、圓餅、人）；清單的圖示底用縮寫字母而不是圖示。
- 沒有圖表的軸線數值、沒有真實頭像照片。
- 只有一支手機的一個畫面；參考圖常是三支手機並排。
- 沒有測直式（9:16，只有手機）、沒有換其他動效風格測、沒有看 3D 風格。
