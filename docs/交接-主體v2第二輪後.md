## 3. 3D 閃爍（上一輪的重點，務必讓使用者實機確認）

使用者回報「很多 3D 主題會閃爍，主要是陰影」。我在 `scripts/design-sheet/sheet.html` 的探針（`__flick`、`__flickScan`）下找到並修了三個原因：①接觸陰影平面與展示台頂面共面的 z-fighting（**有量測**：還原舊做法相鄰幀差異 2.31% → 修正後 1.58%）；②側面陰影痘（`normalBias` 0.03→0.09、`bias -0.0015`、貼圖 1024→2048、`PCFSoftShadowMap`）；③我自己 3D 文字的擠出層互相穿插。改動在 `src/engine/three/common.ts`、`stage.ts`、`materials.ts`（`shadowCatcher` 抬高 0.012＋polygonOffset；`kit.mesh` 新增 `receive` 選項）。
**沒確認的**：使用者的真實 GPU／真實播放下還有沒有別的閃爍來源；我只在內建瀏覽器的離屏接觸表裡量。另外「8-bit 風格看起來不像像素」的回報，我找到一個疑似原因（WebGL 被瀏覽器收回後後期特效永久失效，已加自動重建，`postfx/PostFX.ts`、`renderer.ts`），**沒有在使用者環境確認**；若他重新整理後仍不像素，請查「後期強度」滑桿是否為 0、風格權重是否被稀釋。

## 5. 工具：接觸表（每個主體都是這樣檢查的）

```text
1. preview_start 啟動 .claude/launch.json 的 style-fusion（埠 5199）。若 5199 被別的對話佔用，先確認是不是自己的 session 的伺服器。
2. 另開背景：node scripts/design-sheet/recv.mjs "<scratchpad>/sheets"   （接收器埠 5555；用完要關，Windows 用 taskkill //PID）
3. 內建瀏覽器開：
   http://localhost:5199/scripts/design-sheet/sheet.html?s=<主體id>&v=2&style=<風格id>&m=<動效id>&n=<格數>&cols=<欄>&w=<每格寬>&ar=1.88&t0=0.1&t1=0.9&name=<檔名>
4. 用 Read 讀 "<scratchpad>/sheets/<檔名>.png"
   其他： ?all=1 冒煙測試（window.__n 應為 1260、window.__errs 空）；?bench=1 每幀耗時（window.__bench）
   自訂動畫主題：s=custom&theme=<專案內的檔案路徑，網址編碼>（先匯入該主題檔再畫；只存在預覽瀏覽器）
   檢查主題檔：npx tsx scripts/design-sheet/check-theme.ts <主題檔>（用 App 自己的解析器，列出錯誤與提醒）
```

重點：**要用使用者舞台實際的長寬比（「填滿」約 1.88:1），不要只看 16:9**；動畫的每個時間點都要看（上次通知蓋住標題就是這樣漏掉的）；至少看 `flat`、`popart`、`pixel8`、`cyberpunk`、`watercolor`；3D 用 `cel3d`、`matte3d`、`clay3d`、`wire3d`。**目前 3D 主體大多只用 `cel3d` 看過，這是已知缺口。**

下載參考圖：Dribbble 標籤頁（例如 `https://dribbble.com/tags/bauhaus`）用內建瀏覽器開，`javascript_tool` 從 `document.documentElement.outerHTML` 用正規式抓 `cdn.dribbble.com/userupload/…` 圖片網址，再 `curl -sL -A "Mozilla/5.0" -H "Referer: https://dribbble.com/" "<網址>?resize=800x&vertical=center"` 下載到暫存資料夾，做成接觸表再用 Read 看。**圖檔只放暫存資料夾，不放進專案**（專案裡只有自己用程式畫的圖形）。

## 6. 技術約定（改設計時要守，延續舊交接文件 §3）

顏色只用色板角色或由它們 `mix`／`darken`／`lighten` 算出（不寫死色碼，否則 136 種風格換不了色）；所有東西透過 Brush（`S`）畫；動畫是時間的純函數（只用 `M` 的 `u`、`tw`、`stag`、`fl`…，不累積狀態）；時間結構（`loop`、`key`、`hero`、`events`、`cues`、`track`）沿用 v1；`S.look.detail` 低時省略細節；像素化風格下小字讀不出來，用 `S.look.post` 裡 `pixelate` 的 `size × 400` 估一格像素，改畫色條；背景襯景要中性柔和、跟著背景亮度走；3D 場景三角面要少（低多邊形與線框模式用 `kit.coarse`）；效能 640×360 每幀 2D 不超過約 6 ms。

## 8. 環境陷阱（補充，延續 `HANDOVER.md` §11）

- bash 工具對含引號／中文的長 heredoc 會壞（甚至整段不執行）：長檔案用 **Write 工具**寫到暫存資料夾，再用短的 python 腳本拼接。`python` 可用，`python3` 不行。Python 在 Windows 終端機印中文會亂碼，需要時用 `PYTHONIOENCODING=utf-8`（檔案本身是 UTF-8，沒壞）。
- Python 腳本做批次取代時，每個 `assert old in s` 都要留著；找不到時整個腳本會中止、什麼都不會改（這次遇過，檢查後再重跑）。
- 內建瀏覽器常是「隱藏」的：截圖可能逾時、`requestAnimationFrame` 不跑；接觸表只靠 `Renderer.render`，不受影響。`javascript_tool` 單次上限約 45 秒，長測試拆開（冒煙測試約 25–30 秒，可先 navigate 再分次讀 `window.__n`）。
- 開發伺服器有時會被別的對話佔用或在換日後停掉：`preview_start` 若報埠被佔用，先看是不是自己 session 的；失效時重新 `preview_start`，PNG 接收器也要重開。
- 測試完要關 PNG 接收器（埠 5555）與清掉暫存頁面；不要在專案根目錄留測試檔。
