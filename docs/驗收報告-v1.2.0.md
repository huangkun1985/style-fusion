# Style Fusion v1.2.0 驗收報告

> 版本：1.2.0（2026-10-03）　性質：次版本（新增「名曲庫」並大幅修正 XM 方案；舊的收藏、配方碼、本機設定都能繼續用）
> 前一版：`驗收報告-v1.1.2.md`。完整更新內容見 `CHANGELOG.md`。

---

## 1. 這一版要解決的問題

**使用者驗收意見**：程式自己編寫的曲子聽起來不夠好聽，想要加入經典老歌（歐美流行、日本動漫、純音樂等各種類型）。

**能做與不能做的部分（已在對話中說明）**：現代流行歌與動漫歌曲的旋律受著作權保護，即使只是轉成音符資料也算重製，所以不放進專案。這一版先收**已進入公共領域**的經典，並讓每首都能換成任何一種編曲風格，用「同一首歌的不同編曲」來補足多樣性。使用者自己的歌，建議走下一版的「匯入 MIDI」（檔案只在瀏覽器本機處理）。

## 2. 這一版有什麼

聲音分頁新增「名曲」區塊（在「曲風」上方）：

| 分組 | 曲目 | 建議編曲 |
| --- | --- | --- |
| 古典名曲 | 歡樂頌、卡農、給愛麗絲、G 大調小步舞曲、C 大調前奏曲、土耳其進行曲（主題）、山魔王的洞窟、命運動機 | 古典鋼琴、電影管弦 |
| 民謠與節慶 | 鈴兒響叮噹、小星星、雅克兄弟（輪唱） | 民謠、原聲吉他流行、古典鋼琴 |

- 選一首之後，「曲風」標題變成「**編曲風格**」，「自動」選項寫成「自動（這首的建議編曲）」；選任何一種曲風，就是用那種風格的低音、伴奏、鼓與音色演奏同一首旋律。
- 「目前的音樂」標題會寫成「歡樂頌 · 爵士編曲 · C 大調 · 105 BPM」；理由欄第一行寫名曲與作曲者。
- 與原有功能的關係：與動畫循環對齊（整首剛好是動畫循環的整數倍，必要時整首重複 2–4 次）、調性選項（整首移調）、速度偏好、聲音方案（8-bit、Game Boy、SID、FM、MIDI、XM）、導出（WAV、MIDI、XM、MP4 音軌）、試聽自動跟隨，全部照常運作。
- 「重新作曲」鈕在選了名曲時只影響鼓點細節（旁邊的文字會說明）。
- 不選名曲（預設）時，行為與 1.1.2 完全相同。

### 順手修的 bug
「鋼琴切分」伴奏（流行、城市流行曲風）在一小節兩個和弦時，第二個和弦的低音加強沒有檢查長度，會產生長度 0 的音，最後一小節還會超出歌曲結尾。舊曲風都是一小節一個和弦，所以過去沒碰到。

## 4. 沒有驗證的事（請你聽）

- **沒有人聽過。** 我聽不到聲音。旋律是我依記憶寫成音符資料的，可能有錯音或節奏不對，請聽了告訴我哪一首、哪一小節哪裡怪，我會對照修正。
- 我**較有把握**的：歡樂頌、小星星、鈴兒響叮噹、雅克兄弟、命運動機、C 大調前奏曲（和弦與琶音型）、小步舞曲。
- 我**較沒把握**的地方（優先聽這些）：
  - **給愛麗絲**：弱起位置與中間「C–E–A」琶音的八度（我放在中央 C 起算）。
  - **土耳其進行曲**：前八小節較有把握，最後的收尾句是我自己接的終止式。
  - **山魔王的洞窟**：第三句（B–C♯–D–E–F♯–D–F♯–B–A–F♯–D–F♯–A）與「F 自然音」那一句的和弦。第二輪是整個高八度重複，原曲是逐漸加快加強，這裡沒有做漸快。
  - **卡農**：低音進行與最上聲部（二分音符那一圈）是原曲；後三圈的旋律變奏是我在這個和弦進行上自己寫的，不是原曲的任何一段。
- 編曲是現有曲風的規則生成，不同曲風配上同一首旋律，有些組合（例如把山魔王配上 Chip 或把前奏曲配上嘻哈）可能很怪，這是預期內的，好不好聽要靠你判斷。
- 每首只取主題或前段（不是整首作品）。

## 5. 已知限制

- XM 方案只有一個 256 列的樂段，所以每首（含重複）最多 256 個 16 分音符；因此沒有收長篇的作品。
- 名曲的 BPM 為了與動畫循環對齊，會在原速附近浮動（約 ±10%）；關閉「對齊動畫循環」就是原速。
- 2/4 與 3/8 的曲子被併成 4/4 與 3/4 小節，鼓型與伴奏以併起來的小節為單位。

## 5b. XM 方案的修正（使用者回報：XM 比 8-bit 還難聽）

**做法**：我聽不到聲音，所以用同一首歌分別渲染 MIDI 與 XM，逐軌量測音符數、響度、亮度與頻譜，找出差異的來源。

| # | 問題（量到的數據） | 原因 | 修正 |
| --- | --- | --- | --- |
| 1 | 只保留 65% 的音符（有的曲風旋律少一半） | 上一個音的「放開」標記（key-off）佔住下一個音的起點，前後相接的音被當成格子已占用而丟掉 | 新音可以蓋掉放開標記；保留率 100% |
| 2 | 旋律比 MIDI 小聲 15–18 dB，鼓只小聲 6 dB；頻譜重心 220–400 Hz（MIDI 520–910 Hz） | XM 沒有 MIDI 的聲部比例與音量基準；鼓的取樣沒縮放，母帶標準化後鼓蓋過旋律 | 套用同一組聲部比例；鼓降 10.5 dB；全部聲部落在 −17～−19 dB |
| 3 | 取樣鼓亮度只有 MIDI 的 1/3 | 鼓被降到 22 kHz，高頻全沒了；也少了衰減 | 鼓維持原取樣率並帶上相同衰減 |
| 4 | 合成器音色（主奏、低音、鋪底）比取樣樂器大聲 5–17 dB | 用程式生成的 8-bit 小取樣，沒有校準 | 校準表 `xmCalibration.ts`（跨音區、音長量測） |
| 5 | 鋼琴平均要拉伸 2.1 個半音 | 每個樂器只留 8–10 個音區 | 用滿 16 個（拉伸 1.1） |
| 6 | 琶音與旋律斷斷續續、琶音偏小聲 7 dB | 單聲道：每彈下一個音就切掉上一個音的餘音 | 主旋律 2、和聲 2、琶音 3 條聲道輪流，和弦最多 8 條 |
| 7 | 高頻 3–5 dB 偏少、有折疊雜音 | 22.05 kHz 加上粗糙的降取樣 | 32 kHz（低音區 16 kHz、中音區 24 kHz 省空間）+ 加窗 sinc 低通 |
| 8 | 殘響與 MIDI 不同 | 整體固定 22% | 與 MIDI 同一組設定、同樣的各聲部送量 |

**結果**：同一首歌，整體頻譜重心 XM 441 Hz／MIDI 519 Hz（流行）、885／912 Hz（古典）；動態起伏 0.38／0.37；34 個曲風中，聲部之間的音量差距多數小於 3 dB（最大是鐵克諾 7 dB，它的主奏只有 6 個極短的音）。
**與 libopenmpt 的一致性**：自製播放器渲染 .xm 與 libopenmpt 解碼比對，鼓與主旋律包絡相關係數 1.00；整體約 0.95（鋪底等持續音疊在一起的細微起伏造成，包絡形狀本身一致）。
**代價**：.xm 檔從 1.6–2.3 MB 變成 2.5–4.4 MB；聲道數最多 20 左右（格式上限 32）。

**仍沒驗證**：以上全是數據，**沒有人聽過**。XM 本來就是 16 位元單聲道取樣加追蹤器效果，音質上限低於 MIDI 方案（沒有速度層、沒有逐音的濾波與顫音），請你聽過之後告訴我還差在哪裡。

## 5c. 古典鋼琴與純樂器曲風

**使用者回報**：點「古典鋼琴」出來的是小提琴；鋼琴類型一定要是鋼琴，並且要有其他樂器的純樂器類型。

**原因**：曲風表裡 `classical` 的主奏是 40 號音色（小提琴）、鋪底 48（弦樂）、低音 43（低音大提琴）；而且鼓組程式在三拍子時不管鼓型是不是 `none`，都會加上華爾茲鼓。

**修正與新增**
- 古典鋼琴：主奏、低音、和弦都是鋼琴，沒有鼓；鼓型 `none` 的曲風現在完全不產生鼓。
- 新增 12 種純樂器曲風（共 46 種），聲音分頁新增「純樂器（沒有鼓）」一組：鋼琴獨奏、小提琴、大提琴、古典吉他、長笛與豎琴、薩克斯風、豎琴、弦樂四重奏、銅管合奏、顫音琴與馬林巴、管風琴、八音盒。
- 驗證：逐一列出每個曲風的聲部與樂器（古典鋼琴＝鋼琴／鋼琴／鋼琴；古典吉他＝尼龍吉他三聲部；弦樂四重奏＝小提琴×2、大提琴、弦樂鋪底…），都沒有鼓；MIDI 與 XM 渲染檢查全部正常；XM 與 MIDI 的聲部音量差在 2 dB 內。
- 名曲的預設編曲改用這些曲風（歡樂頌、卡農→弦樂四重奏；給愛麗絲、土耳其進行曲→鋼琴獨奏；小星星→八音盒；雅克兄弟→長笛與豎琴）。

**沒有驗證**：沒有人聽過。旋律仍是規則生成（名曲除外），有些樂器在某些音域可能不自然（例如長笛的高音、大提琴的低音），請聽過後告訴我。

## 5d. 靈感骰子、舞台填滿、全螢幕

**使用者意見**：靈感骰子也要把音樂一起隨機；展示區在一般畫面下要能用完所有空間（左右還有空白）；要有全螢幕展示的按鈕。

| 項目 | 做法 | 驗證 |
| --- | --- | --- |
| 骰子連音樂 | `randomize` 同時抽新的種子、曲風、聲音方案、調性、速度，約 30% 抽名曲；不動聲音開關與音量 | 連按 6 次：每次種子、曲風、方案、名曲、調性、速度都不同 |
| 骰子連主體與微調 | 一定換成不同的主體（用到 3D 材質／運鏡時挑 3D 主體，約 10% 跨界）；微調（速度、循環長度、線條、後期強度、色板混合、種子）約半數維持原樣；自訂色板清掉 | 連按 60 次：主體 0 次重複、14 種主體抽到 13 種；3D 材質配 3D 主體；抽卡 14 次畫面無錯誤；提示「已隨機：主體、風格、動效、微調與音樂」 |
| 鎖定音樂／主體 | 混合配方區新增「音樂」「主體」鎖定鈕（鎖鑰匙存在 `locked` 裡的 `a:music`、`s:subject`） | 鎖定後再按骰子：音樂（主體）完全不變、風格照樣換；提示「已隨機（主體已鎖定，沒有更動）」 |
| 填滿 | 新比例 `fit`（預設）：舞台框＝整個舞台區；比例限制在 0.4–2.6，導出用當下的比例 | 視窗 1440×900：選 16:9 左右各空 102 px，選填滿＝0 px |
| 全螢幕 | 播放列按鈕、F 鍵、連點兩下；先立刻鋪滿視窗，再向瀏覽器要求原生全螢幕，答應了就升級；控制列 2.6 秒淡出；Esc／F／按鈕離開 | 真實點擊：舞台 1440×900 鋪滿、控制列出現；F 鍵離開再進入、Esc 離開都正常 |

**發現並修掉的問題**：內嵌預覽視窗對全螢幕請求既不答應也不拒絕，原本「等結果再決定退路」的寫法會卡住。改成「先鋪滿視窗，原生全螢幕當作加分」。

**沒驗證**：真正的瀏覽器全螢幕（內嵌視窗拒絕）、手機、多螢幕。全螢幕時的 Esc 在原生模式下由瀏覽器處理。

## 5e. 配方碼與收藏帶著音樂（B-02）

**起因**：靈感骰子變成全部抽卡之後，抽到喜歡的組合卻只能存下畫面，音樂（含名曲）收藏或分享後就沒了。

**做法**：`SavedMix.audio` 與配方碼的 `a` 欄位（陣列：曲風、方案、音效包、對齊、種子、速度、調性、名曲）。配方碼維持 `SF1.` 前綴、向下相容；載入時用 `cleanMusic`（沿用 `sanitizeAudioPrefs`）整理成合法值。不存聲音開關與音量。

**驗證**：`npm run test:audio` 新增往返、舊格式（沒有音樂）、壞資料整理三項測試；瀏覽器實測：抽卡 → 收藏 → 再抽兩次 → 載入，音樂與主體都還原且音量不變；從分享視窗取碼 → 再抽 → 貼上載入，音樂、主體、風格都還原；壞碼被拒絕。

## 5f. 匯入 MIDI

**使用者意見**：要能匯入 MIDI，而且目的不只是播放，要能轉成 8-bit、XM 或其他格式。

**做法**（`src/audio/midiImport.ts`）：用 `@tonejs/midi` 解析 → 整理成與自動作曲相同的 `Song`（多軌音符、角色、音色、和弦、調性）→ 之後的聲音方案、導出（WAV、MIDI、XM、MP4 音軌）、試聽、移調、速度偏好、與動畫對齊，全部沿用，不需要為匯入另寫一份。

| 項目 | 結果 |
| --- | --- |
| 解析 | 測試用 MIDI（程式自己產生的原創編曲：鼓、貝斯、鋼琴、弦樂鋪底、長笛，20 小節）：5 軌、20 小節、120 BPM、C 大調，角色 chord／lead／bass／pad／perc；GM 音色號保留；不支援的鼓號（52／55／58）會對應到支援的 |
| 壞檔 | 亂碼、空檔、沒有音符的 MIDI 都丟出清楚的錯誤訊息，介面顯示「匯入失敗：…」 |
| 與動畫對齊 | 動畫 2.2／3.2／4.2／8 秒：整段剛好是動畫循環的整數倍，速度在原速 ±25% 內；不對齊時是原速 |
| 段落 | 取第 5 小節起 8 小節：128 步、音符數約為全曲的 40%；起點超過全曲時退回有內容的段落 |
| 移調 | 選 G：旋律整體平移 7 個半音（可差八度） |
| 6 種聲音方案 | NES、GB、SID、FM、MIDI 取樣、XM 都能演奏，無 NaN、無削波（瀏覽器實測 0.35–1.9 秒） |
| 導出 | WAV（RIFF）、MIDI（可被標準解析器讀回，音符數一致）、XM（20 小節＝320 列＝2 個樂段，16 聲道；用 libopenmpt 解碼長度與自製播放器相同） |
| 瀏覽器 | 開發版與正式版（單檔）都實測：真實的檔案選取、單軌多聲道（format 0）檔案、段落、換方案、重新整理後還在、移除 |

**沒驗證**：
- **沒有用真實的商業編曲 MIDI 試過**（我手上沒有，也不該內建）。真實的 MIDI 常有複雜的變速、多聲道混在同一軌、很密的音符，角色判斷（誰是主旋律）可能猜錯；猜錯的話聲音仍然正常，只是 8-bit 的聲道分配與混音比例不理想。請你用自己的檔案試，告訴我哪裡怪。
- 很長、很密的檔案渲染會比較久（MIDI 取樣方案最慢，主執行緒會卡住幾秒）；XM 會是幾 MB 到十幾 MB。
- 8-bit 方案是把每個軌道用固定的音色演奏，不是逐音符模擬真正的 NES 四聲道限制，同時發聲數很多的和弦會被做成快速琶音。

## 5g. 走路循環、XM 音質、取樣包、匯入動畫主題

### 走路循環「同手同腳」
`walk.ts` 手臂的相位與腿接反（近側腿往前時近側手也往前）。對調後，近側腿往前時近側手在身後、遠側手往前。瀏覽器全螢幕放大截圖確認。

### XM 音色質量（量化）
**方法**：`scripts/xm-quality.ts` 以 20 種樂器、同一段參考旋律（跨 2–3 個八度、長短音、力度起伏）分別用 MIDI 取樣與 XM 渲染，`scripts/xm-quality.py` 比較長時間平均頻譜（1/3 八度）、高頻、包絡、12 kHz 以上能量。

| 指標 | 基準線 | 修正後 |
| --- | --- | --- |
| 音色差（平均，dB，越小越接近 MIDI） | 1.27 | **0.72** |
| 高頻差（絕對值平均，dB） | 2.67 | 1.70 |
| 12 kHz 以上多餘能量（dB） | +10.3 | +5.7（絕對值約 −64 dB，聽不到） |

找到的問題：(1) 持續音循環接縫每 0.3 秒凸／凹一下（重取循環＋自己做交叉淡化，兩端不同相）→ 改用取樣包原本驗證過的循環，並讓循環長度對應整數個樣本；(2) 線性插值的鏡像雜音 → 4 點 Hermite、逐樣本音量漸變；(3) 每個樂器只放 8–16 個音區 → 每個音用最近的取樣、只放用得到的音區、放不下拆成多個 XM 樂器；(4) 對所有主旋律（連鋼琴）加通用顫音 → 依樂器，和 MIDI 一致。

**沒驗證**：**沒有人聽過**。指標只能說「和 MIDI 方案更像」；XM 的音質上限仍受取樣本身（單聲道 MP3、Tone.js 樂器庫的音區密度）限制。持續音的包絡相關仍偏低（0.56–0.73），但單音包絡形狀兩邊一致，那是兩個渲染各自的細微起伏（顫音）不同步造成，不是缺陷。

### 取樣包補密
從取樣來源補上沒用的音（管風琴 +10、尼龍吉他 +5、簧風琴 +4、小提琴 +5、低音大提琴 +3…，共 +43 個音區；原本就已間距 ≤3 個半音的樂器沒動）。取樣包 5.3 → 6.07 MB。
**沒做**：換成「品質更高」的取樣來源（例如 VSCO 2 CE 的完整錄音）。評估後這次不做：Tone.js 庫已經是同一批錄音的精選，真正限制音色的是少數樂器（低音大提琴、低音號、木琴、鐘琴）音區稀疏，改來源需要逐樂器研究檔名與力度層、重新驗證授權（CREDITS）、檔案再大好幾 MB，風險與成本偏高；先請你聽過新版，再決定要不要針對特定樂器升級。
