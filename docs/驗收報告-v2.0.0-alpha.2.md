## 4. 修改卡與復原（實測，用貼回的方式，不花額度）
- 預覽 → 按住比較（舞台換回原本的主體與風格）→ 放開（回到結果）→ 放棄：主體、風格、主題都回到原本的，歷史 0 步。
- 預覽 → 套用：1 步；復原回到模板、重做回到生成的內容。
- 預覽中改速度：卡片自動變「已套用」，歷史 2 步；第一次復原退速度、第二次退 Agent 的修改。
- 手動模式（`?agent=manual`）：沒有送出鈕；「複製提示詞」拿到 6 KB 的修改提示詞（含目前的 JSON 與你的話）；貼回一份改了一個值的回答 → 卡片「改了 1 個值」→ 放棄後 JSON 完全還原。當時「動到的時間」顯示 0.2–7.8 秒（把整條軌道都算進去，太寬）；改成只算變了的那個鍵的前後兩段，這部分由 `scripts/agent-test.ts` 驗證，沒有在瀏覽器裡重看。

## 6. 審查問題（實測）
- **R-05**：同一道連送三首長配樂（每首約 3 秒）：中間那首立刻被取消，最新那首 5.9 秒到（以前要等前兩首做完，約 8.8 秒）。正在做的那一首沒辦法中途停（同步渲染），這是剩下的等待。
- **R-07**：建立改成共用 Promise（讀程式確認；同時進來的情況沒有刻意重現）。
- **R-19**：模擬壞一次 → 重建、下一首正常；模擬連續壞兩次 → 永久退回主執行緒，進行中的那首在主執行緒做完。`messageerror` 本身沒有辦法在瀏覽器裡造出來，是讀程式確認。
- **R-20**：先量：18 種樂器解碼後 97 MB、鼓 3 MB，兩邊各一份就是兩倍。改成送過去之後主執行緒放掉；實測放掉後第二首不再解碼、主執行緒重新解碼的渲染和背景執行緒逐樣本相同（最大差 0）。

## 7. 沒有驗證的（直說）
- 實際播放的樣子（只看接觸表）、音效。
- 沒裝／沒登入 Claude Code 的提示畫面。
- 雙擊單檔（file://）下的手動模式（用 `?agent=manual` 代替）。
- 連續十幾輪修改會不會越改越偏；十幾個圖層以上的複雜內容。
- 生成約 40～70 秒、修改 10～20 秒是這幾次的數字；換主題、換模板會不一樣。
- 「附上時間點」附的是文字資料，沒有附那一格的縮圖（提案 3.4 的第 ④ 項）——Claude Code 的無畫面模式這次沒有測傳圖，留到之後。

## 8. 我自己定的小決定
- 生成的結果也用修改卡（套用／比較／放棄），和修改一致。
- 超過 6 ms 不自動重問（會再花額度），改成卡片上的「請 Agent 簡化」鈕。
- 預覽中改了別的東西＝接受結果（不然歷史會很混亂）。
- 生成時同時換成模板的風格與動效（提案：生成之後這個場景綁定這個風格模板）。
- 重問時，卡片上的摘要用第一次回答的（第二次只會說「修正了字型」）。
