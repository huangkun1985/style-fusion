## 1. 版本介紹：v1.1.0 是什麼

**一句話**：給動效設計師的「風格參考台」。選圖像風格、選動效風格，任意混搭，即時看到動起來的樣子，並拿到色板、緩動曲線、CSS／GSAP／AE 表達式、AI 提示詞，還能導出動畫與配樂。純網頁，不需要安裝或打包成 exe。

### 1.1 這一版有什麼（相對 v1.0.0）

| 項目 | v1.0.0 | v1.1.0 |
| --- | --- | --- |
| 圖像風格 | 115 | **133**（含 25 種真 3D） |
| 動效風格 | 58 | **68**（含 10 種 3D 運鏡） |
| 案例配方 | 40 | **53**（其中 12 個是首次開啟的「起點」） |
| 主體 | 10（只有 1 個真 3D） | **14**（5 個真 3D） |

- 聲音預設關閉（瀏覽器規定要先點一下才能出聲）：點播放列的喇叭，或按 **M**

## 2. 驗收範圍與方法

**環境**：Windows 11、Claude 桌面版內建瀏覽器（Chromium 內核）、RTX 4090。
**對象**：開發伺服器版與 `dist/index.html` 正式版（正式版以本機伺服器開啟測試）。

| 類別 | 做法 |
| --- | --- |
| 需求對照 | 逐條對照你的三項需求（第 3 章） |
| 全量渲染掃描 | 腳本把每個圖像風格套在每個主體上渲染 2 個時間點，檢查例外、空白畫面、耗時 |
| 動效掃描 | 每個動效風格 × 每個主體渲染 3 個時間點，檢查例外與非法數值；另取整圈畫面比較「最後一幀→第一幀」是否跳動 |
| 音訊 | 96 種「曲風 × 聲音方案」逐一渲染，檢查有無 NaN、削波、音量；檢查循環接縫；檢查與時間軸的同步；`npm run test:audio` |
| 導出 | 所有格式實際導出，檢查檔頭、軌道數、內容；MP4 音軌解碼後與原混音做互相關 |
| 介面 | 桌面與手機寬度、深淺色、鍵盤快捷鍵、起點選擇器、聲音分頁 |
| 異常輸入 | 故意寫入損壞的本機設定，看頁面是否能自救 |
| 無障礙與效能 | 對比度計算、元素命名檢查、載入時間、WebGL 內容數 |

**限制（請記得）**：內建瀏覽器視窗常被隱藏，這時動畫不會被繪製，所以**真實的畫面幀率沒有量**；我也**無法聽音樂**。這兩項列在第 8 章，請你實際驗收。

## 4. 驗收通過的項目（附數據）

### 4.1 視覺與動效
- 3,724 次「風格 × 主體」渲染：0 例外、0 空白畫面。
- 2,856 次「動效 × 主體」渲染：0 例外、0 個非法數值（NaN／無限大）。
- 3D 每幀耗時（640×360）：多數 2.3–3.5 毫秒；第一次用到某材質或場景會有 70–220 毫秒的一次性卡頓（見 B-05）。
- 縮圖：上百張縮圖共用渲染器；整頁只用 4 個 WebGL 內容（上限約 16），沒有耗盡風險。

### 4.2 聲音
- 96 種組合全部能渲染：無 NaN、峰值不超過 1.0、音量落在合理範圍（RMS 0.03–0.3）；單首渲染 0.1–1.3 秒（在視窗被隱藏、計時器被節流的環境測得，實際通常更快）。
- 同步：BGM 與時間軸誤差約 5 毫秒；暫停後 BGM 停止；拖曳／跳轉後 1–10 毫秒內重新對齊；0.5× 慢放時 BGM 跟著慢放。
- 音效：在動畫的起跳、落地等「提示點」準時觸發，每個循環重複。
- 循環接縫：音樂結尾到開頭的跳變，不大於曲子裡任何一個普通音符起音的跳變（8-bit 方波的硬起音本來就會有「啪」的邊緣，屬於音色特性）。
- `npm run test:audio` 全部通過（循環對齊、作曲、MIDI／XM 結構、85 個音效變體）。
- MIDI 用獨立解析器讀回驗證；XM 用 libopenmpt（經 ffmpeg）解碼驗證，與自家播放器的音量包絡相關係數 0.96。

### 4.3 導出
| 格式 | 實測結果 |
| --- | --- |
| MP4（含音訊） | 兩條軌道（影像＋AAC）；解碼後音訊與原混音對齊 0 取樣、相關係數 0.9997 |
| GIF | 有效 GIF89a，約 0.9 MB（360p） |
| WebM | 有效檔案，即時錄製（約 4 秒） |
| PNG 序列（ZIP） | 47 幀 360p 約 10.4 MB |
| 精靈圖 | 7×7 拼圖正常 |
| 單張 PNG | 可產出，但 3D 有 B-01 問題 |
| WAV／MIDI／XM | 檔頭與長度正確 |

### 4.4 穩健性
- 損壞的本機設定（非法曲風、非數字音量、超範圍速度）載入後自動整理成合法值，頁面不會空白。
- 最外層加了錯誤畫面，萬一出錯可「重新載入」或「清除本機資料」。
- 鍵盤：空白鍵、方向鍵、O／P／G／R／M 皆正常；焦點在按鈕上時空白鍵不被攔截。
- 手機寬度（375px）：播放列、分頁、聲音分頁、起點選擇器都沒有溢出。

## 5. 問題清單

**嚴重度**：P1＝影響核心輸出或造成資料遺失；P2＝影響完整性或可用性；P3＝體驗與優化。
**工作量**：S＝半天內；M＝1–2 天；L＝3–5 天；XL＝1 週以上。

### 5.1 產品問題

#### B-01　P1　3D 主體的存圖與導出，第一幀是「載入 3D 場景…」占位卡　〔工作量 S〕
- **現象**：選 3D 主體後按舞台工具列的相機鈕「存下目前畫面」，PNG 裡沒有 3D 模型，只有一張「載入 3D 場景…」的圓角卡片。動畫導出（GIF／MP4／WebM／ZIP／精靈圖）的**第 0 幀**也一樣，GIF 每次循環會閃一下占位卡。
- **重現**：切到「3D 角色」→ 按相機鈕 → 打開下載的 PNG。或導出精靈圖看左上角第一格。（已在正式版實測確認。）
- **原因**：導出和存圖每次都新建一個渲染器，3D 模組是「非同步」載入的；第一次渲染時還沒載好，就畫了占位卡。
- **影響**：所有 3D 風格的單張輸出都不能用；動畫輸出的第一幀不能用。3D 是這一版最主要的新賣點，所以列 P1。
- **建議**：導出與存圖開始前，先等 3D 模組與場景準備好才渲染第一幀（或直接沿用主舞台已就緒的 3D 舞台）；等待時在導出視窗顯示「準備 3D 場景…」。
- **驗收條件**：對每個 3D 主體導出 PNG、GIF、MP4，所有幀（含第 0 幀）都沒有占位卡。

#### B-02　P2　配方碼與「我的收藏」不含聲音設定　〔M〕
- **現象**：調好曲風、聲音方案、音效包、速度、調性、種子之後，複製配方碼或收藏，換個地方還原，聲音全部回到預設。
- **原因**：配方碼只記錄風格、權重、主體、微調；收藏記錄的欄位也沒有聲音。（依程式確認。）
- **影響**：「同一首歌」無法分享或重現，違背「配方可完整還原」的承諾。
- **建議**：配方碼升級為第 2 版格式並**繼續能讀舊版**；聲音設定（不含開關與音量）一起編碼；收藏同樣記錄。

#### B-03　P2　風格處方、代碼、AI 提示詞完全沒有聲音內容　〔M〕
- **現象**：「處方」只講視覺與動效；「代碼」沒有音效提示表；「AI 提示詞」沒有音樂／音效提示詞。
- **影響**：設計師拿到處方後，聲音這塊要自己重新想一遍；要找真人作曲或用 AI 生成音樂時，沒有現成的描述可貼。
- **建議**：處方新增「聲音處方」（速度、調性、曲風、聲音方案、音效包、每個音效出現的時間點）；代碼分頁新增「音效提示表」（JSON／CSV，之後可擴充 AE 標記）；AI 提示詞新增「音樂」與「音效」兩段（中英各一）。

#### B-04　P2　次要文字對比度不足，且有大量 11px 以下小字　〔S〕
- **數據**：輔助文字色在淺色主題下對比 3.5:1、深色主題下 3.4–3.6:1（標準要求 4.5:1）；淺色主題的強調色（動效橘）在面板上 3.95:1。介面中 57 處文字小於 11px。頁面沒有任何 `h1` 標題。
- **影響**：在螢幕反光、年長使用者、投影時不易閱讀；螢幕閱讀器缺少頁面主標題。
- **建議**：輔助文字色調深／調亮到 4.5:1 以上；最小字級提到 12px；加上 `h1`（可視覺上隱藏）與主要區域標記。

#### B-05　P2　第一次用到某個 3D 材質、場景或後期特效會卡一下　〔M〕
- **數據**：第一次渲染玻璃、珍珠、卡通 3D 材質時單幀 100–220 毫秒；第一次切換到 3D 主體還要載入 Three.js。其後都是 2–6 毫秒。
- **影響**：點到新風格的瞬間畫面頓一下，縮圖牆第一次滑到 3D 區也會有些許延遲。
- **建議**：頁面閒置時在背景預先編譯常用材質與特效（預熱）；3D 載入完成前顯示骨架畫面而不是只有文字。

#### B-06　P3　聲音的細節體驗　〔M〕
- 暫停時拖曳時間軸**完全沒聲音**，無法「邊拖邊聽」找節拍（建議加短促的擦洗音）。
- 慢放時音高會跟著降（0.25× 會降兩個八度），音效變得很怪（建議慢放時音效不變調，或慢放時自動靜音音效）。
- 切換聲音方案或曲風時，舊音樂在新音樂就緒前持續播放，然後**硬切**到新的（建議交叉淡入淡出）。
- 喇叭按鈕不顯眼，新使用者可能不知道有聲音功能（建議首次使用給一次性提示）。

#### B-07　P3　少數動效在整圈循環的接縫處有輕微跳動　〔M〕
- 掃描 68 × 14 = 952 種組合，4 組的「最後一幀→第一幀」差異約為平常相鄰幀的兩倍：`彈性 iOS × 幾何`、`錯峰 × UI`、`姿勢對姿勢 × 幾何`、`文字亂碼 × UI`。肉眼是否明顯待你確認。
- 建議：逐組檢查，必要時調整循環長度的取整方式。

#### B-08　P3　音效覆蓋不均　〔M〕
- 各主體的提示點數：UI 12 個、幾何 14 個、圖表 10 個，但**風景、抽象流動、3D 地形只有 2 個**，等於只有配樂、幾乎沒有音效。
- 建議：為這類主體加入環境音床（風聲、嗡鳴、水流）與更多提示點；並允許使用者在聲音分頁逐一開關音效類型。

#### B-09　P3　音樂風格集中　〔L〕
- 133 種圖像風格對應到 38 種「曲風 × 方案」組合；**52%（69 種）使用 MIDI 方案**，41% 使用「自然」音效包；曲風以氛圍（19）、電子（15）、可愛（14）居多。
- 影響：不同風格的音樂容易聽起來相似，這與你先前抱怨預設案例「太單一」是同一類問題。
- 建議：降低 MIDI 預設比例、為每種曲風增加多種旋律／節奏型態，並建立「聽感對照表」讓你標記哪些風格聽起來不像。

#### B-10　P3　WebM／GIF 沒有聲音；MP4 音軌依賴瀏覽器的 AAC 支援　〔M〕
- WebM 可補音軌（以音訊串流錄製）；GIF 本來就沒有聲音。
- MP4 的 AAC → Opus → 無聲影片三層退路，只實測了第一層（AAC）。

#### B-11　P3　音樂渲染在主執行緒　〔L〕
- 作曲後的音訊合成在主執行緒分段進行，單首約 0.1–2 秒，期間介面可能稍有停頓；分頁被隱藏時用計時器讓步會更慢。
- 建議：移到 Web Worker 或專用音訊執行緒。

#### B-12　— 　`.xm` 檔長度與動畫有 0.5% 內差異　〔不處理〕
- XM 格式的速度只能是整數 BPM，屬格式限制。已在說明中註明。

### 8.2 聽感驗收清單（請逐項勾選，回報給我）
1. 開聲音，選「掌機冒險」起點：像不像掌機遊戲？音量是否舒服？
2. 同一首歌，在分頁裡逐一按 6 個方案的 ▶ 試聽：6 種音色**是否真的有明顯差別**？哪一種最不像它的名字？
3. 切換 16 種曲風：有沒有「聽起來都差不多」或「很難聽」的？請寫下曲風名。
4. 角色跳躍主體：起跳與落地的音效是否對上畫面？
5. 把速度偏好拉到 0.7 與 1.4：太慢或太快的邊界在哪？
6. 音樂循環一圈接回開頭時，有沒有「啪」一聲或節奏斷掉？
7. 音量：音樂與音效的比例是否合適？是否需要預設再小聲一點？
8. 導出 MP4 播放：音畫是否同步？
9. 用音樂軟體打開導出的 `.mid` 與 `.xm`：能否正常播放？

### 8.3 十分鐘功能驗收步驟
1. 清除瀏覽器本機資料後重新開啟 → 應出現「選一個起點」。
2. 勾選「附帶音樂與音效」→ 選「合成波夜色」→ 應有 3D 地形與音樂。
3. 風格庫切到「3D 渲染（真 3D）」→ 縮圖應逐漸出現。
4. 右側「聲音」分頁 → 看歌名、鋼琴捲簾、播放頭是否隨時間移動。
5. 按 M → 聲音關／開；按空白鍵 → 暫停，音樂應停。
6. 導出 → MP4（勾選加入音樂與音效）→ 用播放器看有沒有聲音。
7. **（驗證 B-01）** 切到 3D 角色 → 按相機鈕存圖 → 檢查是否為占位卡。
8. 縮小視窗到手機寬度，檢查分頁與播放列。

## 9. 版本管理規範（之後每次升級照這個做）

### 9.1 版本號規則
- 修訂版（1.1.**x**）：只修問題，不加功能。
- 次版本（1.**x**.0）：新增功能或內容；**舊的收藏、配方碼、本機設定必須能繼續用**。
- 主版本（**x**.0.0）：有不相容改動才升；升級說明放在該版本紀錄第一段。

### 9.2 每次發版要交付的東西
| 項目 | 位置 | 內容 |
| --- | --- | --- |
| 版本紀錄 | `CHANGELOG.md` 最上方新增一節 | 新增／變更／修正／已知問題（沿用現有格式） |
| 驗收報告 | `docs/驗收報告-vX.Y.Z.md` | 本文件的縮短版：這一版驗了什麼、通過什麼、剩什麼問題、下一版計畫 |
| 版本號 | `package.json` 的 `version` | 與紀錄一致 |
| 成品 | `dist/index.html` | 重新建置 |
| 標籤 | git tag `vX.Y.Z` | 建立版本控制後（E-01） |

### 9.3 發版前檢查清單
1. `npm run typecheck` 通過。
2. `npm run test:audio` 通過（之後加入的測試也要全過）。
3. `npm run build` 成功，記下檔案大小。
4. 全量渲染掃描 0 例外、0 空白（本次使用的掃描腳本日後整理進 `scripts/`）。
5. 本文件 8.3 的十分鐘驗收跑一遍。
6. 上一版的「已知問題」逐條標註：已修／延後／不處理。

### 9.4 升級與相容性說明（寫給使用者）
- **本機資料**：收藏、微調與偏好存在瀏覽器的 `style-fusion-v1` 項目。1.1.0 讀得到 1.0.0 的資料；聲音偏好是新增欄位，缺少時自動補預設。
- **配方碼**：`SF1.` 開頭的舊配方碼在所有 1.x 版都能載入。若 1.2.0 引入第 2 版格式，會維持讀取舊版。
- **聲音預設**：每次開啟頁面聲音一律關閉（瀏覽器規定），不會被保存為開啟。
- **同一首歌的重現**：同一組風格、曲風、方案、種子、速度、調性永遠產生同一首歌；若某版升級了作曲演算法，會在紀錄中註明「同樣設定的音樂會改變」。
